«Пытался разные скиллы юзать, всё равно слопно достаточно получается», — [написал участник моего чата](https://t.me/ohld_chat/44546), когда искал способ делать лендинги через Claude. Знакомый результат: аккуратные карточки, большая кнопка, красивый градиент. И ощущение, что этот сайт ты уже видел раз сто.

Ниже — восемь дизайн-скиллов для Claude Code и Codex. Одни помогают выбрать внешний вид страницы, другие доводят кнопки и анимации, ещё два нужны для игр. У каждого есть конкретная задача. Ставить всё сразу смысла нет.

Собрал рекомендации из чата и проверил актуальные репозитории. Чужой опыт отмечен ссылками на сообщения. Порядок работы ниже — моя рекомендация для старта; сравнения восьми инструментов на одном лендинге я не проводил.

## Какие дизайн-скиллы выбрать

Для первого сайта я бы начал с **frontend-design**, а готовый экран отдал **Impeccable** на разбор. Если проблема в ощущении от кнопок, меню и переходов — посмотрел бы на **Emil** или **better-ui**. Для игровой графики нужны другие инструкции.

Порядок ниже — от универсального старта к более узким задачам. Звёзды относятся ко всему репозиторию, а не к отдельному скиллу. Числа и даты последнего push проверены 17 ноября 2026 года; сами по себе звёзды хороший дизайн не гарантируют.

## Как установить скиллы в Claude Code и Codex

Скилл — папка с `SKILL.md`, иногда со скриптами и примерами. Агент читает её, когда задача подходит под описание. Про остальной набор инструментов есть [моя подборка скиллов и MCP](/luchshie-skills-mcp-claude-code-agent-browser/), а про подключение — [настройка Claude Code](/claude-code-nastrojka-mcp-hooks-skills-2026/).

Команды ниже запускаются **в терминале из папки проекта**. В установщике `npx skills add` выберите Claude Code или Codex; можно выбрать оба. Чтобы указать агент явно, допишите `-a claude-code` или `-a codex`. Без глобального флага установка относится к проекту.

После установки откройте новую сессию. В Claude Code вызовите скилл через `/имя-скилла`, в Codex — через `$имя-скилла` или меню `/skills`. У плагина имя может содержать префикс: выбирайте то, которое показывает ваш агент. Самый понятный вариант для обоих: «Используй скилл … и сделай …».

В каждом примере ниже можно отправить один и тот же запрос в Claude Code и Codex. У Impeccable и UI UX Pro Max свои установщики — их команды указаны отдельно. Установщики через `npx` требуют Node.js; дополнительные требования конкретного скилла тоже стоит проверить до запуска.

## С чего начать: frontend-design и Impeccable

### 1. frontend-design — чтобы у сайта появился свой стиль

[Официальный frontend-design от Anthropic](https://github.com/anthropics/skills/tree/main/skills/frontend-design) задаёт агенту роль дизайнера: разобраться, для кого продукт, выбрать палитру, типографику и композицию под эту задачу. Не хвататься за первый привычный шаблон.

Что меняется: вместо одинакового оформления для кофейни, игры и аналитического сервиса агент получает требование связать внешний вид с предметом сайта. Для лендинга детской игрушки и рабочего дашборда это должны быть разные решения.

```bash
npx skills add anthropics/skills --skill frontend-design
```

Запрос для Claude Code или Codex: «Используй frontend-design. Сделай главную небольшого отеля у моря: реальные фотографии, крупная типографика, удобное бронирование с телефона. Сначала покажи один экран».

**Когда пропустить:** у продукта уже есть утверждённые макеты, компоненты и брендбук, а задача — аккуратно добавить поле в форму. Новое художественное направление тут только мешает.

В чате этот скилл [советовали именно для Codex](https://t.me/ohld_chat/35009). Надпись Anthropic на репозитории не означает, что инструкции полезны только Claude.

### 2. Impeccable — чтобы объяснить агенту, что именно поправить

[Impeccable](https://github.com/pbakaus/impeccable) даёт набор команд для работы с готовым интерфейсом. `critique` разбирает дизайн, `typeset` — шрифты и типографику, `layout` — отступы и ритм, `polish` — финальные детали. Есть и проверка технических проблем через `audit`.

Это удобно, когда «сделай красивее» уже не работает. Можно указать один экран или блок и получить конкретные замечания: что первым притягивает взгляд, где тесно, почему цена теряется среди подписей.

Установка для обоих агентов:

```bash
npx impeccable install
```

Выберите нужный агент и установку в проект. Затем в Claude Code — `/impeccable init`, в Codex — `$impeccable init`. Этот шаг собирает контекст продукта. Для разбора тарифов используйте соответственно `/impeccable critique блок тарифов` или `$impeccable critique блок тарифов`.

Если установщик добавил автоматическую проверку дизайна, в Codex откройте `/hooks` и подтвердите проектный hook. Без этого автоматическая проверка не запустится; сам скилл можно вызывать вручную.

**Когда пропустить:** вы ещё не решили, что пользователь должен сделать на странице. Полировка не выберет за вас продуктовую задачу. Начать с одной секции полезнее, чем просить переделать весь сайт.

Impeccable вместе с Emil и UI UX Pro Max [назвали в чате в ответ на вопрос о фронтенд-скиллах](https://t.me/ohld_chat/52589). Это рекомендация участников, не сравнительный тест качества.

## Для готового приложения: Emil и better-ui

### 3. emil-design-eng — чтобы интерфейс приятно реагировал

[Скиллы Emil Kowalski](https://github.com/emilkowalski/skills) посвящены деталям взаимодействия. Основной `emil-design-eng` помогает с состояниями нажатия и наведения, поведением всплывающих элементов, переходами и анимациями.

Что меняется: кнопка понятнее отвечает на нажатие, меню появляется из логичного места, переход не тормозит действие. Пользователь может и не сформулировать, почему стало приятнее. Но это видно, если открыть два варианта рядом и потыкать.

```bash
npx skills add emilkowalski/skills --skill emil-design-eng
```

В Claude Code или Codex: «Используй emil-design-eng. Проверь открытие меню и переключение вкладок. Убери задержку при частых действиях, сохрани доступ с клавиатуры. Покажи результат в браузере».

**Когда пропустить:** странице не хватает понятной структуры или нормального текста. Анимация не объяснит непонятный продукт. Для таблицы, по которой человек кликает весь день, лишнее движение может только раздражать.

### 4. better-ui — чтобы убрать мелочи, из-за которых всё выглядит недоделанным

[better-ui из набора Jakub Krehel](https://github.com/jakubkrehel/skills/tree/main/skills/better-ui) работает с оптическим выравниванием, скруглениями вложенных элементов, тенями, иконками и откликом на нажатие.

Типичная задача: на экране уже всё есть, но иконка кажется кривой, радиус внутренней карточки спорит с внешним, а переключение темы на секунду размазывает цвета. Здесь скилл даёт агенту конкретные правила, по которым это можно исправить.

```bash
npx skills add jakubkrehel/skills --skill better-ui
```

Для обоих агентов: «Используй better-ui на панели настроек. Сохрани плотность и компоненты проекта. Проверь иконки, вложенные скругления и переключение темы. Исправь найденные несостыковки».

**Когда пропустить:** вам нужен полный аудит доступности или новая дизайн-система. У автора для этого есть отдельные скиллы. Сам `better-ui` покрывает визуальную доводку, а не все возможные проблемы интерфейса.

Emil и better-ui пересекаются. Для одного компонента я бы выбрал кого-то одного, иначе агент может по очереди применять разные правила к одной и той же анимации.

## Другие варианты для сайта: Taste и UI UX Pro Max

### 5. design-taste-frontend — когда хочется более выраженного дизайна

[Taste Skill](https://github.com/Leonxlnx/taste-skill) — более подробный процесс для сайта: выбрать визуальную систему, собрать страницу и проверить её в настоящем браузере. В текущем репозитории основной скилл называется `design-taste-frontend`; часть старых скиллов автор перенёс в отдельные репозитории.

Он задаёт больше ограничений на композицию, изображения и единообразие элементов. Полезен для корпоративного сайта, портфолио или продуктовой страницы, когда результат без инструкций слишком похож на случайный шаблон.

```bash
npx skills add Leonxlnx/taste-skill --skill design-taste-frontend
```

У текущей версии нужны Node.js 22+ и установленный Chrome, Edge или Chromium. В Claude Code или Codex: «Используй design-taste-frontend. Собери сайт студии керамики по этим фотографиям. Сохрани цвета изделий, проверь мобильный первый экран в браузере».

**Когда пропустить:** нужен маленький фикс в существующем приложении или точное воспроизведение макета. Этот процесс шире задачи. Taste я бы пробовал как альтернативу frontend-design, а не подключал оба на каждый запрос.

[Участник чата рекомендовал Taste v2](https://t.me/ohld_chat/52591) в сентябре. Команда выше ведёт к текущему скиллу, а не закрепляет ту сентябрьскую версию.

### 6. UI UX Pro Max — когда нужно выбрать основу дизайн-системы

[UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) содержит каталоги стилей, палитр, типографики и UX-рекомендаций. По описанию продукта агент может подобрать основу оформления, затем применить её к конкретному стеку.

Полезный результат — согласованные цвета, шрифты и роли компонентов вместо независимого выбора на каждом экране. Например, сначала оформить систему для сервиса бронирования, затем собрать поиск, карточку и форму оплаты в её рамках.

Для Claude Code:

```bash
npx ui-ux-pro-max-cli init --ai claude
```

Для Codex:

```bash
npx ui-ux-pro-max-cli init --ai codex
```

Для поиска по каталогам нужен Python 3. В ноябре 2026 актуальный npm-пакет называется `ui-ux-pro-max-cli`; старое имя `uipro-cli` осталось в прошлых инструкциях.

Запрос в обоих агентах: «Используй UI UX Pro Max. Предложи дизайн-систему для кабинета бронирования на React. Учти длинные русские названия и формы с ошибками. Сначала покажи палитру и один экран».

**Когда пропустить:** нужен узнаваемый авторский стиль, а вы готовы выбрать только название из каталога. Подбор палитры не заменяет референс, реальные фотографии и понимание задачи.

## Для игр: графика в одном стиле и удобный HUD

В [обсуждении игры для Яндекс Игр](https://t.me/ohld_chat/57467) Арсений поделился своим набором инструментов для графики, интерфейсов и звука. Среди них — набор gamedev-skills. Для этой подборки я выбрал из него два скилла, которые относятся именно к внешнему виду и читаемости игры.

### 7. create-game-assets — чтобы персонажи и окружение не спорили друг с другом

[create-game-assets](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/tree/main/skills/disciplines/create-game-assets) помогает зафиксировать стиль и технические требования к игровым ассетам. Палитра, ракурс, размер, контуры, освещение — всё, что легко разъезжается при генерации каждой картинки отдельным промптом.

Что меняется: сначала появляется один утверждённый образец, затем семейство совместимых спрайтов, иконок или тайлов. Скилл также требует проверять прозрачность, размеры и то, как графика выглядит внутри игры.

```bash
npx skills add gamedev-skills/awesome-gamedev-agent-skills --skill create-game-assets
```

В Claude Code или Codex: «Используй create-game-assets. Нужны герой и три противника для 2D-игры. Сначала зафиксируй палитру, ракурс и размеры. Сделай одного героя, покажи его на игровом фоне. После выбора продолжим остальных».

**Когда пропустить:** вам нужна только работа с меню или импорт уже готовых спрайтов в движок. И ещё: скилл не содержит бесплатную модель генерации картинок. Для создания изображений агенту нужен отдельный инструмент; без него можно подготовить требования или подобрать готовую графику.

### 8. game-ui-ux — чтобы меню работало на нужном экране

[game-ui-ux](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/tree/main/skills/disciplines/game-ui-ux) отвечает за HUD — здоровье, счёт и другие показатели поверх игры, — а также за меню, масштабирование и навигацию.

Что меняется: текст остаётся читаемым, кнопки не уезжают под вырез телефона, меню можно пройти с геймпада. При открытии диалога фокус не должен уходить на кнопку позади него. Это те вещи, которые на красивом скриншоте легко не заметить.

```bash
npx skills add gamedev-skills/awesome-gamedev-agent-skills --skill game-ui-ux
```

Запрос для обоих агентов: «Используй game-ui-ux. Проверь меню паузы и HUD на телефоне и 16:9. Сохрани пиксельный стиль. Покажи переходы между меню и проверь управление без мыши».

**Когда пропустить:** нужны сами персонажи, текстуры или баланс уровней. Этот скилл про интерфейс. Для реализации в конкретном движке добавьте подходящий скилл из того же репозитория; игровую логику ради оформления переписывать не надо.

## Как совместить скиллы в одной задаче

Я уже [писал про «покажи, не рассказывай»](https://t.me/danokhlopkov/1612): дизайн проще оценить в интерактивном прототипе. Поэтому сначала один экран, потом весь сайт.

Для нового веб-проекта попробуйте такую последовательность:

1. Дайте frontend-design конкретный продукт, референс и материалы. Получите один экран.
2. Выберите направление. Сохраните палитру, типографику и компоненты, чтобы следующие страницы на них опирались.
3. Попросите Impeccable разобрать экран. Исправьте несколько главных проблем.
4. Если взаимодействия ещё ощущаются сырыми, отдайте один компонент Emil или better-ui.
5. Откройте результат на телефоне и десктопе. Нажмите кнопки, введите длинный текст, вызовите ошибку формы.

Вот промпт для первого прохода — подставьте свой продукт и приложите референс:

```text
Используй frontend-design.
Делаем сайт маленькой студии керамики. Цель — записаться на занятие.
Вот фотографии работ и референс. Объясни, что берёшь из референса.
Сохрани существующий стек проекта.
Сначала сделай первый экран и карточку занятия, без остальных страниц.
Покажи в браузере на ширине 390 и 1440 px.
Проверь длинное название занятия и кнопку записи.
После моего выбора зафиксируй цвета, шрифты и отступы.
```

Следующим сообщением: «Используй Impeccable critique для этих двух блоков. Назови три главные проблемы и предложи исправления». Так понятнее, какое изменение сработало. А если после установки очередного скилла всё ещё выходит одинаковый сайт — начните с референса и задачи, которую человек должен решить на странице.
